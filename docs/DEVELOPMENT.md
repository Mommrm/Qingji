# 轻记 Android 1.3.1

原生 Kotlin / Jetpack Compose / Room / DataStore 记账应用。本机保存人民币收支与手动维护的资产余额，无登录、广告、网络权限，不自动读取微信、支付宝、短信或银行余额。

## 1.4.1 账户分型与还款（当前版本）

- 账户性质由 `kind` 决定，不再靠余额正负推断：`ASSET_KINDS` = 银行卡／微信／支付宝／现金／其他（5 类，可归入流动资金或理财资金）；`DEBT_KINDS` = 信用卡／花呗／信用支付／其他（4 类，key 为 `DEBT_OTHER`，不参与资金池）。`ACCOUNT_KINDS` 是两者并集，`isDebtKind()` 是唯一判定入口。**Room schema 仍为 v3，本次不改表结构。**
- 负债账户录入时填正数表示欠款，保存为负的 `openingBalance`，全程不需要负号；列表、详情、下拉选择器统一用红色 + 「欠款」字样，按绝对值显示。负债账户固定 `pool = LIQUID`，账户性质创建后不可修改（`saveAsset` 校验），避免因符号翻转造成历史流水错乱。
- `assetTotal()` 只累加资产类账户的正余额，`assetDebtTotal()` / `debtAccounts()` / `debtSlices()` 只统计负债类账户的负余额；资产类账户的负余额不算负债，负债类账户的正余额（溢缴）也不计入总资产。资产页账户列表分「资产账户 / 负债账户」两组，各带小计。
- 资产 → 负债的转账在 UI 上标为「还款」，转入负债账户会让欠款减少；`saveTransfer` 拦截还款后余额转正的情况（"还款金额超过当前欠款"）。反向为「借款」，欠款与资产同时增加。两者都不计收支。
- 校准余额对负债账户改为「校准欠款」，输入正数、内部传负 target；金额键盘不加负号。备份解码时允许负债账户负期初与负 `targetBalance`，并把旧备份里负债类账户的正期初自动翻负（旧版无负号）。
- `Repository.initialize()` 每次启动幂等修正历史数据：负债类账户若期初为正，翻负后写回。条件本身自消除，无需迁移标记。
- versionCode=7，versionName=1.4.1，数据库仍为 v3、schemaVersion 仍为 3，签名沿用原版。

## 1.4 资金池、负债口径与预算标记迁 Room

- 资产账户新增「流动资金 / 理财资金」归属。总资产 = 两池正余额之和；负债账户不冲减总资产，资产页用独立红色饼图按账户列出欠款构成，首页「资产」同样只显示正余额合计。资产分布圆环仍只画正余额账户。此时资产与负债仍按余额正负区分，1.4.1 起改为按账户类型分组（见上）。
- 记账表单新增「流动账单 / 理财账单」。切换后资产账户选择器只列对应池的账户，并自动选中该池首个账户；退款跟随原支出的资金类型。账户换池时，挂在该账户上的账单资金类型由 `saveAsset` 在同一事务内同步更新。流动资金与理财资金之间的划转走现有转账，总资产不变、两池小计变化。
- 「还款」「计入预算」标记从 DataStore 迁到 Room 的 `entries` 表（`inBudget` / `repayment`），与账单保存共用同一个事务，消除原先跨库两次提交的非原子问题。`budgetExpense`、`excludedBudgetEntries`、`isRepayment` 只读账单字段，旧 `Settings` 里两个集合仅用于兼容旧备份。
- Room `version = 3`，新增 `MIGRATION_2_3`（`entries.pool / inBudget / repayment`、`asset_accounts.pool`）。App 首次启动用 `v3BudgetFlagsMigrated` 标记做一次性搬运：把旧偏好中的 `budgetExcludedEntries` / `repaymentEntries` 写回账单字段后清键；先写 Room 再打标，重复启动幂等，禁止破坏性清库。
- 备份 `schemaVersion = 3`，新增账单与账户的 pool、账单预算标记；读 v1/v2 备份时会把 settings 里的旧标记回填到账单字段。CSV 增加资金类型、计入预算、还款三列。
- 余额、收支、退款、归档账户、回收站与恢复流程的其余规则不变。versionCode=6，versionName=1.4.0，签名沿用原版；升级安装前仍建议导出一次完整备份。

## 1.3.1 首页左滑操作

首页账单向左滑动，显示“备注”和“删除”两个按钮。备注直接编辑，无需打开整张记账表单；删除立即隐藏账单并同步还原余额，可从底部提示撤销。一次只展开一行，右滑或点击该行可收起；完整滑过也不会自动删除。

删除入口已从输入页“更多”中移出。操作失败仅显示简短状态，不显示失败原因。原有退款关联、归档账户与余额保护规则保持不变。备注采用数据库事务读取最新账单后仅修改备注与审计字段，不覆盖金额、账户和日期，也不会恢复已删除账单。

versionCode=5，数据库仍为2，签名沿用原版。安装前先导出JSON备份，再覆盖安装。

## 1.3快速输入

| 操作 | 默认流程 |
| --- | --- |
| 记账 | 选分类 → 输入金额 → 保存；账户默认最近使用项，日期默认今天 |
| 新增资产 | 选银行卡/微信/支付宝等图标 → 填余额 → 保存；名称自动生成，可点铅笔改名 |
| 转账 | 选转出、转入账户 → 输入金额 → 保存 |
| 校准 | 输入实际余额 → 保存；显示当前与校准后余额对照 |

- 数字键盘和保存按钮固定在底部，表单内容可单独滚动；金额最多八位整数、两位小数，按分保存。
- 备注点击后编辑；记账的时间、连续记账、同步余额与退款入口位于“更多”；删除与快速备注位于首页左滑菜单。旧账只关联状态直接显示“仅关联”，默认行为不变。
- 新建资产可直接保存0余额；校准须明确输入目标余额，避免空值误清零。
- 微信、支付宝使用独立品牌矢量图标，银行卡、现金和其他账户使用对应图形；图标用于账户列表、选择器及账单账户标识。品牌色保持识别，不随主题改变。
- 资产分布环形图仅统计使用中的正余额；有负余额时标为“正余额分布”。（1.4 起总资产不再按净额计算，1.4.1 起负债按账户类型单独统计。）
- 首页及原统计、预算、备份规则沿用1.2；数据库仍为2，versionCode=4，继续使用原签名。未新增权限。

- 明细页顶部以主题色呈现月度收支、结余与预算，账单按日期分组并显示每日收支；搜索覆盖全部账本（备注、分类、资产），不受当前选中月份限制，命中结果显示完整日期。
- 底部为明细、图表、中间记账、资产、我的；预算与攒钱位于“我的 → 账本工具”。

- “我的 → 主题与外观”可选暖阳黄、森林绿、海盐蓝、暮光紫、玫瑰粉，或输入#RRGGBB自定义色；实时全局生效、重启保留。

- 包名与签名不变，versionCode=3。数据库仍为2，无新表或旧账变更。
- 布局参考鲨鱼记账官网公开截图（https://www.shayujizhang.com/），分类使用Material Icons，保留轻记自身名称与功能。

## 1.1资产功能（已保留）

- 新增独立“资产”页，可添加多张银行卡、微信、支付宝、现金及其他账户，查看余额合计和各账户流水。
- 添加账户时填写当前已有余额，作为期初余额，不计收入。支出选择付款资产，收入/退款选择到账资产；仍可“不关联资产”。
- 记账修改金额、切换资产、删除与撤销后，余额按有效流水自动重算，不会重复扣减。
- 账户间转账同时更新两边，不计收入或支出；余额不符可用“校准余额”记录差额，也不计收支。
- 1.0旧账升级后默认未关联、不影响余额；补关联时默认只关联。只有主动开启“同步调整资产余额”，才纳入余额计算，避免新录入的当前余额被重复扣款。
- 余额允许因漏记而为负，会显示提示；有余额的账户不能直接归档，应先转出或校准至0。归档后历史保留，可恢复。
- 攒钱进度继续独立，不重复加进总资产。JSON备份schema2包含全部资产流水，并兼容1.0的schema1备份。
- 1.1使用原签名，versionCode=2。安装前建议导出一次完整备份，再覆盖安装；不要卸载旧版。升级为Room数据库1→2显式迁移，不清空旧账。
- 这是本地账面记录，不连接支付平台，不会移动真实资金。没有增加系统权限。

完整规则与示例见 `docs/QingJi-Assets-Design-V1.md`。

## 安装与使用

1. 将 `QingJi-1.3.1.apk` 发到安卓手机，点击安装或覆盖升级。最低 Android 8.0。
2. 系统如提示“允许此来源安装应用”，仅为当前文件管理器或浏览器开启安装来源许可；它不是轻记读取手机内容的权限。
3. 首次安装从空账本开始，覆盖升级保留旧账。使用底部中间“＋”记录收支；点击明细可修改或记录退款；首页左滑可备注和删除。底部包含明细、图表、记账、资产、我的。
4. 分析支持日、周、月、年和自选区间，点击分类筛选明细，底部可导出当前期间完整收支 CSV。
5. "我的 → 预算与攒钱目标"包含总预算、分类预算与攒钱目标。默认预算只影响设置时当月及后续未单独设置的月份，不追溯旧月份。攒钱进度不参与收支。记一笔时可勾选「还款」（还信用卡、花呗等），或单独关闭「计入预算」（报销、代付等）；这类账单仍计入收支与资产余额，只是不占用预算。标记按账单保存，编辑账单可随时改，预算设置里可查看本月已排除账单并恢复计入。资产页的"信用卡""花呗""信用支付"自 1.4.1 起属于负债类账户，只记欠款、不计入总资产，也不影响预算；还信用卡请用「转账 / 还款」，与账单上的「还款」预算标记是两回事。
6. 记账提醒默认关闭，主动开启时才申请通知权限；关闭时隐藏全部提醒设置。开启后可选提醒时间（23:00前）、重复方式（每天／工作日／周末，或自定义任意星期组合）、当天已记账跳过，并显示下次提醒时间。系统省电、厂商限制、强制停止可延迟或阻止送达；重新打开应用会检查调度。
7. 设置中可归档/恢复分类、跟随系统/浅色/深色、完整 JSON 备份与恢复。JSON 用于完整恢复，CSV 用于表格查看。
8. 备份恢复前会显示摘要，确认后替换账本，并在本机保存恢复前快照。可用“恢复上次导入前的本地快照”恢复。每次恢复会更新这份快照；不是无限版本历史。恢复后提醒默认关闭。恢复状态与写入任务保存在 ViewModel，旋转屏幕不会中断或丢失；偏好写入与常规设置更新共用同一把互斥锁。
9. 卸载或清除应用数据会删除本地账本及本地恢复快照，请先把完整 JSON 备份保存到应用外。

## 统计口径

- 金额以 Long 分存储，单笔最大 99,999,999.99 元，最多2位小数。当前资产余额由期初及有效流水统一计算。
- 净支出 = 支出 − 当期退款；结余 = 收入 − 净支出，不表示银行卡余额。
- 预算消耗 = 扣除「不计入预算」账单后的净支出；退款按其关联的原支出是否被排除判定，不按退款自身判定。首页预算剩余、总预算与分类预算使用同一口径，收支统计与资产余额不受影响。账户类型、付款账户均不参与预算判定。
- 退款关联原支出，累计不超过原金额，按退款日冲减原分类支出，支持跨月与跨资产到账。原支出有有效退款时需先删退款才能删除原支出。改原付款资产不自动移动已发生退款的到账资产。
- 当前月按截至今天的天数与上月同期对比，历史完整月对比上一个完整月；零基数或负净支出时不生成误导的增长百分比。
- 所有删除收支采用软删除；删除后可在提示中撤销，或在「我的 → 已删除账单」恢复。恢复退款单时若原支出也被删除会一并恢复；已归档账户关联的账单不可恢复。
- 攒钱存入/取出记录为独立事件，不创建收支记录。进度历史可回看，错误金额可用反向事件调整。
- CSV 以带 BOM 的 UTF-8 输出，转义引号/换行并防止备注等文本被表格软件当作公式。

## 在 Android Studio 构建

打开本目录，使用 JDK17，安装 SDK35 和构建工具，等待 Gradle 同步。项目固定 AGP8.7.3 / Gradle8.9 / Kotlin2.0.21，依赖版本显式固定；不是动态最新版本。

调试构建：`gradlew.bat assembleDebug`。发布构建：先还原独立保存的签名材料，再运行 `gradlew.bat testDebugUnitTest lintRelease assembleRelease`。Release 默认执行 R8 缩减。

## 用 PowerShell 构建

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\Setup-Android.ps1
.\Build.ps1 -DebugBuild
# 同一签名的后续正式升级：还原自己的签名材料后
.\Build.ps1
```

默认发布构建要求 `signing.properties` 和它引用的签名文件。签名材料单独交付，未包含在普通源码包中；把独立备份中的 `private-signing/` 和 `signing.properties` 还原到项目根目录。切勿把签名备份发给朋友，朋友只需要 APK。后续覆盖升级必须使用同一签名、相同 applicationId，并增加 versionCode。

## 数据、权限与后续版本

应用仅声明 POST_NOTIFICATIONS、RECEIVE_BOOT_COMPLETED；依赖可能添加普通内部组件权限，最终清单以测试报告为准。无 INTERNET、精确闹钟、无障碍、短信、定位、悬浮窗、广泛存储权限。通过系统文件选择器仅读写用户选择的备份文件。禁止系统自动云备份与设备迁移，以兑现本地保存边界。

预留 Entry UUID、revision、updatedAt、deletedAt、syncState。云同步、账号、冲突协议、自动记账、共享账本、多币种不属于本版。Room schema version 为3，保留1/2/3的导出schema以及MIGRATION_1_2、MIGRATION_2_3，禁止破坏性清库。提供Android迁移测试与桌面SQLite结构/旧账保留验证，具体已执行范围见TEST-REPORT.md。数据导入严格校验并用数据库事务替换，失败回滚。
